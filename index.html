Teratai lakehouse

snek5/teratai ↗

A fully open-source lakehouse that starts with one docker compose up. It runs Spark on Apache Iceberg tables stored in S3-compatible object storage, with dbt models layered from staging through intermediate and marts to analytics, orchestrated by Airflow through Cosmos.

Services
PostgreSQL 15 as the Iceberg metadata catalog, MinIO with an auto-created warehouse bucket, an Iceberg REST catalog, one Spark master with two workers, and a Thrift server for SQL and JDBC clients.

When will an employee leave?

snek5/kaggle_employee_attrition ↗

Most attrition models predict whether someone resigns. This one treats tenure as time-to-event data, so HR can see how retention decays over time and which factors speed it up or slow it down. Built on the IBM HR Analytics dataset.

Ŝ(t) = ∏tᵢ ≤ t (1 − dᵢ / nᵢ)Kaplan–Meier estimate of the share of staff still employed at tenure t.
Methods
PCA to collapse correlated pay and seniority variables, Kaplan–Meier curves with log-rank tests, a log-normal accelerated failure time model and Cox proportional hazards, compared by AIC.
Output
Hazard ratios and tenure effects a manager can read directly, plus retention recommendations.

Portfolio Optimizer v2

snek5/mvo ↗

An interactive Streamlit app for allocating across a basket of assets. The optimisation engine is a standalone Python library, kept separate from the interface so it can be reused in other projects.

maxw  wᵀμ − (λ/2)·wᵀΣw   s.t. Σwᵢ = 1Markowitz utility, solved as a convex problem with CVXPY and the ECOS solver.
Features
Maximum Sharpe and minimum variance portfolios, efficient frontier, Monte Carlo simulation, Black–Litterman views, allocation limits and a rebalancing calculator.

A Docker image, ready to deploy.

How I work

Simple first, then grow with you

A long-term partner should stay useful as your data matures, without selling you infrastructure before you need it.

You pay for outcomes

Hours of manual reporting removed and decisions made sooner. The infrastructure is how it gets done, not what you buy.

The simplest thing that works

A scheduled script and a PostgreSQL table often beat a cluster. Spark, Airflow and dbt arrive only when your requirements call for them.

Your data stays separate

Each client gets an isolated database, storage and services. No shared tables with other customers.

Supported after launch

Monthly maintenance covers monitoring, fixes and small changes, so reports keep arriving when a source file changes shape.
